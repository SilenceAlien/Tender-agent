## 二、Prompt 优化方案

### 2.1 重构后的 8 章节

见 `optimized_prompts.py`，核心改动：

| 章节 | 优化要点 |
|------|---------|
| sec1 投标函 | 新增报价/税率/保证金/6条承诺/文件清单 |
| sec2 身份证明 | 从授权委托书拆出，独立固定格式 |
| sec3 授权委托书 | 明确委托范围/期限/无转委托/附件 |
| sec4 投标保证金 | **新增**，保函格式+4种保证情形 |
| sec5 偏差表 | **新增**，表格格式+3行分类 |
| sec6 资格审查 | **重构**，7个子项表格格式 |
| sec7 服务方案 | **重大重构**，7个子节全覆盖 |
| sec8 应急保障 | **新增**，替代原"售后服务承诺" |

### 2.2 服务方案 prompt 的 7 个子节

真实标书的服务方案有严格的 7 子节结构，当前 prompt 完全没有：

```
（一）项目概述 → 项目背景+用工需求+服务范围
（二）服务目标 → 合规/高效/安全/优质 四维度
（三）服务团队架构 → 组织结构+岗位设置
（四）服务团队主要职责分工 → 逐岗详述（6个组）
（五）团队保障措施 → 人员保障+培训保障
（六）团队成员背景经验 → 逐人列出（姓名/经验/业绩）
（七）服务承诺 → 6项承诺（合规/质量/效率/保密/责任/信誉）
```

### 2.3 关键新增约束

| 约束 | 说明 |
|------|------|
| 禁用绝对化用语 | "全国第一""唯一""最佳"等（违反广告法） |
| 敏感数据留白 | 统一【待填写：具体说明】格式 |
| 法律文书风格 | 投标函/授权委托书用法律措辞 |
| 表格格式 | 资格审查/偏差表用表格输出 |

## 三、范文优化

### 3.1 现有范文问题

| 问题 | 说明 |
|------|------|
| 类型不匹配 | 劳务外包类范文是**食堂餐饮**，不是**劳务管理** |
| 结构不匹配 | 8章通用结构，与真实标书8部分差异大 |
| 缺少关键内容 | 无报价/无偏差表/无资格审查表格 |
| 服务方案子结构 | 范文是食堂特有结构，非劳务管理结构 |

### 3.2 新增范文

已在 `knowledge_base/劳务管理服务类/范文/` 生成 3 个核心范文：

| 文件 | 来源 | 字符数 |
|------|------|:--:|
| sec1_bid_letter_一、投标函.txt | 真实标书脱敏 | 923 |
| sec7_service_plan_七、服务方案.txt | 真实标书脱敏 | 2488 |
| sec8_emergency_八、应急保障方案.txt | 真实标书脱敏 | 724 |

这些范文保留了真实标书的**结构骨架**和**专业表述**，敏感数据（企业名称、报价金额、人员姓名、身份证号）全部用【待填写：具体说明】格式留白。

## 四、Prompt-Guard 安全扫描

### 4.1 扫描结果

| Prompt | 结果 | 说明 |
|--------|:--:|------|
| sec1 投标函 | ⚠️ 误报 | repetition_detected（结构化模板重复字段名，正常） |
| sec2 身份证明 | ⚠️ 误报 | 同上 |
| sec3 授权委托书 | ⚠️ 误报 | 同上 |
| sec4 投标保证金 | ⚠️ 误报 | 同上 |
| sec5 偏差表 | ⚠️ 误报 | 同上 |
| sec6 资格审查 | ⚠️ 误报 | 同上 |
| sec7 服务方案 | ⚠️ 误报 | repetition + social_engineering_zh（"商业秘密"中的"秘密"被误判） |
| sec8 应急保障 | ⚠️ 误报 | repetition_detected |

### 4.2 误报分析

**全部为误报**，原因：

1. **repetition_detected（8/8 触发）**：结构化 prompt 模板自然重复"投标人名称""盖单位章""法定代表人"等字段名，这是法律文书模板的正常特征，非注入攻击。

2. **social_engineering_zh（sec7 触发）**：prompt 中"保守商业秘密""保密承诺""保密范围"等是标书法律术语，pattern `zh:(秘密|私下)\s*(地)?` 匹配了"商业秘密"中的"秘密"。这是中文法律文本的合法用词，非社会工程学攻击。

**结论**：8 个 prompt 全部安全，无真实注入风险。误报源于 prompt-guard 的中文法律文本适配不足。

## 五、落地建议

### 5.1 立即可做

| 任务 | 文件 | 说明 |
|------|------|------|
| 替换 section_generator.py 的 prompts | optimized_prompts.py → section_generator.py | 替换 `_SECTION_PROMPTS` 和 `DEFAULT_SECTIONS` |
| 索引新范文到 FAISS | knowledge_base/劳务管理服务类/ | 运行 build_knowledge_base.py --type 劳务管理服务类 |
| 新增标书类型 | bid_agent/config/ | 新增"劳务管理服务"类型 |

### 5.2 后续优化

| 方向 | 说明 |
|------|------|
| 评分项注入 | 真实标书的评分要求应逐条映射到 prompt 的 `{requirements_context}` |
| 动态章节 | 不同标书类型应有不同章节结构，不应硬编码 8 章 |
| 表格生成 | 资格审查/偏差表需要表格输出能力，当前 SectionGenerator 只返回纯文本 |
| 范文扩充 | 当前只生成 3 个核心范文，需补齐其余 5 章 |

### 5.3 接入路径

```
optimized_prompts.py
    ↓ 替换
section_generator.py 的 _SECTION_PROMPTS
    ↓
SectionGenerator 调用 get_optimized_section_prompt()
    ↓
FAISS 检索 劳务管理服务类/范文/
    ↓ RAG 注入
生成对标真实标书结构的章节内容
```
