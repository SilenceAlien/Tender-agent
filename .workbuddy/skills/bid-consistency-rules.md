# 标书内容一致性规则 Skill

> 触发条件：标书生成时，涉及多种互斥提交/处理方式的章节
> 适用范围：所有标书类型
> 创建日期：2026-07-07
> 来源：用户发现投标保证金章节同时出现保函格式和电汇回单的矛盾

---

## 问题模式

标书中许多事项存在多种互斥的提交/处理方式。如果提示词同时包含两种方式的格式要素，LLM 会在同一章节中混合输出，导致：

1. **提交形式矛盾**：同一章节要求担保人签章（保函方式）又要求粘贴银行回单（电汇方式），评标专家无法判断实际提交方式
2. **格式要素混用**：保函的担保声明 + 转账的收款账户信息出现在同一文档中
3. **废标风险**：提交形式不明确或矛盾可能被判定为不符合招标文件要求

## 已识别的互斥场景

| 场景 | 方式 A | 方式 B | 矛盾表现 |
|------|--------|--------|---------|
| 投标保证金 | 银行保函（担保人签章） | 银行转账/电汇（回单附件） | 保函格式 + 回单附件同时出现 |
| 投标报价 | 总价包干 | 单价计价 | 同一项目混合两种计价方式 |
| 履约保证 | 履约保函 | 履约保证金 | 同一章节要求两种担保形式 |
| 质保方式 | 质保金 | 质保函 | 混合使用 |
| 合同类型 | 固定总价合同 | 固定单价合同/成本加酬金 | 混用 |

## 处理规则

1. **招标文件已明确指定方式** → 严格按招标文件要求输出，不得出现另一种方式的任何内容
2. **招标文件未明确指定** → 输出选择说明 `【待填写：请根据招标文件要求选择XXX方式】`，然后分别列出各方式的模板，标注"如选择此方式，保留并填写，删除其他方式"
3. **绝对禁止** → 在同一章节正文中同时出现两种互斥方式的格式要素

## 已实施的代码修改

### 1. 全局规则注入（`section_generator.py` → `NO_FABRICATION_DIRECTIVE`）

在防虚构指令末尾追加了「提交形式一致性指令」，列出5类典型互斥场景和处理规则，自动注入到所有章节提示词中。

### 2. 投标保证金章节修复（`optimized_prompts.py` → `sec4_deposit`）

将原来混合保函+回单的单一模板，重构为：
- 顶部添加提交形式一致性要求说明
- 方式一：银行保函（含担保人签章，附保函原件）
- 方式二：银行转账/电汇（含收款/付款账户信息，附回单复印件）
- 标注"如选择此方式，保留并填写，删除其他方式"

## 经验总结

这类错误的根本原因是：提示词编写时直接从真实标书中提取格式，但真实标书只使用了一种方式，而提示词却无意中保留了两种方式的要素。编写涉及多种处理方式的章节提示词时，必须：

1. 识别该事项是否存在多种互斥方式
2. 如果存在，将每种方式分别列为独立模板
3. 添加明确的选择指令，禁止混用
4. 在全局指令中补充该互斥场景，防止遗漏
