# 系统集成类标书提示词模板

<!-- 预估 tokens: ~1000 | 加载条件: 用户明确这是系统集成/数字化建设项目 -->

## 类型核心特征

系统集成采购是 **「设备 + 软件 + 服务」** 的混合体，三种逻辑交织，所有类型中最容易写散。评标委员会最关注：
- 总体架构是否理顺了设备、软件、数据的协同关系（不是各说各话）
- 设备选型是否有充分的兼容性验证（不是参数堆砌）
- 实施部署是否有切实可行的切换和过渡方案（系统集成项目翻车第一名 = 切换失败）

**风格导向**：技术架构牵引，设备参数支撑，项目管理兜底。三层逻辑必须在总体方案下自洽，不能各自为政。

**最大难点**：最怕「设备参数一堆 + 软件功能一堆 + 管理措施一堆」互不关联。核心任务是强制建立三层之间的逻辑连线。

**信创合规提示**：政府系统集成项目几乎必然涉及信创要求，包括服务器、网络设备、安全设备的国产化。《网络安全法》要求关键信息基础设施运营者采购网络产品和服务应通过国家安全审查（网安审查）。

## 统一评分框架映射

| 标准评分维度 | 系统集成对应章节 | 典型权重 | 高分关键 |
|-------------|----------------|---------|---------|
| 整体方案设计 | 总体技术方案 | 20-30% | 设备-软件-服务三层关联映射 |
| 关键技术方案 | 设备选型 + 软件平台 | 30-45% | 逐条参数响应 + 兼容性验证矩阵 + 需求到功能三层映射 |
| 项目实施计划 | 实施部署方案 | 10-15% | 阶段化部署 + 切换方案(数据+过渡+回滚) + 应急预案 |
| 项目团队配置 | （独立章节） | 5-10% | 集成项目经理资质 + 各子系统工程师配置 |
| 培训与运维 | 培训与知识转移 | 5-10% | 分层培训 + 交付物清单 + 质保期SLA |
| 质量安全保障 | 总体方案（安全设计）+ 实施（测试方案） | 5-10% | 等保/密评设计 + 兼容性测试 + 灾备演练 |

## 信创合规矩阵（触发条件：政府客户）

| 设备/软件类别 | 信创要求 | 合规路径 |
|-------------|---------|---------|
| 服务器 | 优先选用国产芯片服务器 | 列入信创目录的产品型号 + 兼容性证明 |
| 网络设备（交换/路由/防火墙） | 通过网安审查 | 国家安全审查通过证明 |
| 操作系统 | 优先选用国产OS | UnionTech UOS/Kylin 兼容性认证 |
| 数据库 | 优先选用国产数据库 | DM8/KingbaseES/GaussDB 厂商兼容性认证 |
| 中间件 | 优先选用国产中间件 | TongWeb/BES 厂商兼容性认证 |
| 安全设备 | 必须通过国密认证 | 商用密码产品认证证书（SM2/SM3/SM4） |
| 应用软件 | 适配国产环境 | 提供适配测试报告 |

## 废标风险清单

| 风险项 | 检查点 | 后果 |
|--------|--------|------|
| 系统集成资质缺失 | 信息系统集成资质/涉密资质等是否在有效期内 | 直接废标或大幅扣分 |
| 设备品牌不在允许范围 | 是否限定品牌或需要同等档次证明 | 符合性审查不通过 |
| 信创不合规 | 关键设备国产化率不达标 | 直接废标（政府项目） |
| 安全产品无国密认证 | 加密设备/CA/密码产品无国密认证 | 安全审查不通过 |
| 兼容性未验证 | 不同厂商设备之间的接口协议未做兼容性说明 | 技术方案扣分 |
| 新旧切换无方案 | 有旧系统但未提供数据迁移和切换方案 | 技术方案不完整 |

## 章节提示词

### 一、总体技术方案（强制设备-软件-服务关联）

```
你是本项目的总体架构师。请撰写「总体技术方案」章节：

【约束】
- 先画逻辑（文字描述）：分层架构（基础设施层→数据层→平台层→应用层→展现层）
- 每一层必须建立三要素映射表：
  | 该层包含的设备 | 部署的软件/平台 | 对外提供的能力 |
  → 这是系统集成标书的核心价值——让评审一眼看到你的集成逻辑
- 关键集成点至少展开 3 个详细说明：
  → 集成点描述（什么和什么对接）
  → 集成方式（接口协议/数据格式/认证方式）
  → 不同厂商设备的互通保证（做过兼容性测试?有案例?）
  → 新旧系统的衔接方案（数据迁移/接口适配/并行期安排）
- 每个关键技术选型（服务器/网络/数据库/中间件/安全/虚拟化）三段论证：
  「选了什么 → 为什么选它（≥2个理由） → 否决了什么替代方案」
- 信创合规说明（如触发）：逐层标注国产化状态
  → 已适配：产品名称+版本+兼容性测试结论
  → 未适配：替代方案+适配计划时间表
- 禁止：设备参数和软件功能分两节独立写——必须融合
  → 评审看到「第二章设备参数、第三章软件功能」直接判定为无集成能力
- 禁止：「采用先进技术架构」而不展开——等于没写
- 风格：架构决策记录 + 集成映射表
```

### 二、设备选型与技术参数

```
你是硬件选型负责人。请撰写「设备选型与技术参数」章节：

【约束】
- 逐条对照招标文件设备参数，三列格式：「招标要求 → 投标响应 → 偏离说明」
- 关键设备必须附带兼容性验证：
  → 与招标要求标准的兼容性（GB/行业标准/接口协议）
  → 与其他拟选设备的兼容性（形成兼容性矩阵表）
  → 与现有系统的兼容性（如果客户有运行中的系统）
- 设备配置清单：名称 | 品牌/型号 | 数量 | 关键参数（与招标要求对比） | 产地 | 信创状态
- 国产化达标情况：对于有信创要求的项目，逐设备标注国产化状态
  → 「国产芯片+国产OS」：提供兼容性认证编号
  → 「进口设备」：说明不可替代的理由和供应链保障
- 正偏离参数突出标注并说明：偏离幅度(数值) + 带来的额外价值
- 禁止：只写参数不写兼容性——集成项目的设备选型不是「参数越高越好」，是「越兼容越好」
- 禁止：不同设备之间参数矛盾（如服务器功率超过UPS承载）
- 风格：参数对比表 + 兼容性矩阵
```

### 三、软件平台方案

```
你是软件架构师。请撰写「软件平台方案」章节：

【约束】
- 功能模块必须与招标文件的业务需求逐条对应对——建立「业务需求→软件功能→技术实现」三层映射表
  → 标准：评标专家拿招标文件的业务需求章节，能在你的方案里逐条找到对应实现
- 技术选型三段论（同总体方案标准）
- 非功能性指标量化：
  → 并发用户数（峰值+基准测试条件）
  → 响应时间（P50/P95/P99分别承诺）
  → 数据容量（当前+3年预估+归档策略）
  → 可用性（如99.9%=年宕机≤8.76h，附实现机制）
  → RPO/RTO（数据恢复点目标/恢复时间目标）
- 如涉及定制开发，明确功能和标准产品的边界
- 必须描述软件与设备层如何交互：
  → 以具体场景说明：比如「视频监控平台如何通过ONVIF协议对接XX品牌摄像头」
- 信创适配（如触发）：说明软件在国产OS+国产数据库上的适配测试状态
- 禁止：功能描述出现「支持」「具备」而无具体方式——说清楚「怎么支持」
  → 反例：「系统支持用户管理」
  → 正例：「基于RBAC模型实现用户管理，支持角色创建/权限分配/组织树同步/单点登录集成」
- 风格：需求→功能→技术实现的逐层映射
```

### 四、实施部署方案（集成项目最容易被低估的章节——实际上翻车率最高）

```
你是项目实施经理。请撰写「实施部署方案」章节：

【约束】
- 实施阶段必须不少于6个阶段，每个阶段五要素：
  输入条件 | 关键活动 | 输出物 | 验收标准(量化) | 参与方(甲方/集成商/厂商)
  → 标准阶段划分：到货验收→环境准备→设备安装→软件部署→系统联调→试运行→正式上线
- 系统切换方案三件套（有旧系统时必须全部覆盖，缺一不可）：
  → 数据迁移方案：迁移范围+迁移工具+数据清洗规则+迁移验证（完整性+一致性）
  → 切换方式：并行运行(推荐，成本高)/逐步切换(推荐)/一次性切换(高风险)
  → 回滚方案：触发条件+回滚步骤+回滚验证+业务影响最小化措施
- 集成测试方案是区分高分和及格方案的关键：
  → 接口测试：测试矩阵(哪些系统接口两两联调)
  → 兼容性测试：设备间兼容性、软件与设备兼容性
  → 性能测试：全链路压测方案
  → 灾备演练：故障注入场景+恢复验证
- 试运行必须量化：时长（天）| 范围（全量/部分）| 通过标准（可用率/故障次数上限）
- 风险最高的3个环节必须有应急预案（不只是风险描述）
- 禁止：试运行没有明确的时长和通过标准——评审会认为你没实际交付过集成项目
- 禁止：切换方案只说「制定详细切换计划」——要写出计划的框架内容
- 风格：甘特图语言+每阶段交付物checklist+风险应急预案矩阵
```

### 五、培训与知识转移

```
你是项目培训负责人。请撰写「培训与知识转移」章节：

【约束】
- 培训按角色分三层，每层说明六要素：
  | 对象 | 内容摘要 | 形式(现场/远程/混合) | 课时 | 人数上限 | 考核方式 |
  → 系统管理员培训（技术深度，涵盖部署/运维/排障）
  → 业务操作员培训（流程操作，涵盖日常操作/常见问题处理）
  → 最终用户培训（界面操作，涵盖基本使用和FAQ）
- 交付文档不少于 6 类，每类描述内容结构：
  → 系统总体设计文档 | 网络拓扑与部署文档 | 设备配置手册 | 软件部署与运维手册 | API接口文档 | 用户操作手册 | 应急预案手册
- 禁止：「提供全面培训」而不分层——系统集成项目涉及设备/软件/网络多维度，不分层 = 无效培训
- 必须：培训考核方式具体化——「上机操作考核+理论考试+模拟故障处置」
- 风格：培训计划表 + 交付物清单，逐条可验收
```
