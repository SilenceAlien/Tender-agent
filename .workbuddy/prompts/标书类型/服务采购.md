# 服务采购类标书提示词模板（v3 — 通用化优化）

<!-- 预估 tokens: ~900 | 加载条件: 用户明确这是服务类项目 -->

## 类型核心特征

服务采购的核心是 **「人 + 流程 + 承诺」** 三位一体。评标委员会最关注：
- 团队是否真有能力交付（不是简历堆砌）
- 服务流程是否可落地执行（不是泛泛而谈）
- 承诺是否有保障机制（不是口头许诺）

**风格导向**：专业但不空洞，用具体方法论和量化数据替代形容词。服务采购是最容易写成「措施大全但实际上什么都没承诺」的类型。

**适用场景**：劳务管理、物业管理、咨询服务、法律服务、财税服务、培训服务、外包服务等人力密集型服务项目。

---

## 统一评分框架映射

| 标准评分维度 | 服务采购对应章节 | 典型权重 | 高分关键 |
|-------------|----------------|---------|---------|
| 整体方案设计 | 服务方案 | 15-25% | 需求理解深度 + 服务目标四维展开 + 方法论具体化 |
| 关键技术方案 | —（服务不强调技术） | — | 服务业的知识/方法论等同于技术能力 |
| 项目实施计划 | 服务方案（实施部分）+ 应急保障方案 | 10-20% | 阶段化推进 + 多场景应急 + 可操作流程 |
| 项目团队配置 | 服务团队配置 | 10-20% | 核心人员资质 + 同类项目经验 + 量化成就 |
| 培训与运维 | 服务方案（培训部分） | 5-10% | 分层培训计划 + 考核方式 |
| 质量安全保障 | 服务方案（保障部分）+ 应急方案 | 5-15% | 质量管控机制 + 合规保障 + 应急可执行 |

**重要说明**：服务采购的评分权重因项目类型差异极大。例如人员外包类项目价格可能占 30-70%（极端案例），而高端咨询服务可能技术占 70% 以上。使用本模板时需根据具体招标文件的评分标准调整策略重心。

## 废标风险清单

| 风险项 | 检查点 | 后果 |
|--------|--------|------|
| 经营许可缺失 | 行业许可证（劳务派遣许可证/人力资源服务许可证等）是否在有效期内 | 直接废标 |
| 业绩不满足 | 同类业绩数量/规模/评价等级是否符合招标文件要求 | 资格审查不通过 |
| 人员资质不符 | 关键岗位人员是否持有指定证书（编号可查） | 团队分大幅扣减 |
| 服务要求不逐条响应 | 招标文件第五章「服务要求」是否有遗漏 | 符合性审查不通过 |
| 报价方式错误 | 是否按招标文件要求的计价单位报价（人/天 vs 人/月 vs 总包价） | 废标或报价分零分 |
| 本地化不满足 | 如要求本地服务团队但未提供本地证明 | 本地化加分项失分 |

## 章节提示词

### 一、服务方案（技术标核心，通常权重最大）

```
你是本项目服务方案设计师。请撰写「服务方案」章节：

【必须包含的结构】
1. 需求理解 — 用自己的语言重述客户需求的核心矛盾点
   → 标准：写完后问自己「这句话可以直接套到另一个同类项目上吗」→ 如果「是」→ 不够具体
2. 服务目标 — 按四维度展开，每项目标 ≤2 句话：
   → 合规目标：「零劳动纠纷」「100%签订率」「社保/公积金0差错」
   → 高效目标：「XX小时完成XX流程」「XX业务办理周期缩短XX%」
   → 安全目标：「工伤率 ≤ X%」「安全培训覆盖率 100%」
   → 优质目标：「满意度 ≥ X%」「投诉率 ≤ X%」
3. 服务团队架构 — 组织层级图(文字描述)，每个岗位说明职责 + 任职要求
4. 服务团队职责分工 — 按职能组展开，每组说明：
   → 职能组名称 | 核心职责(3-5条) | 关键工作流程 | 输出物
   → 常见职能组：项目管理组、合同与档案管理组、薪酬与社保组、培训与考核组、风险与争议管理组、现场管理组(如需驻场)
5. 核心成员背景 — 每人按简历式呈现：年限 | 证书(编号) | 同类项目经验(项目名+规模+角色) | 量化成就
6. 培训保障 — 法律法规培训 | 招标人制度培训 | 业务技能培训 | 安全培训
   → 每项说明：培训内容摘要 | 频率 | 方式 | 考核
7. 服务承诺 — 逐条列出并标注对应的保障措施章节
   → 每条承诺格式：「我们承诺XX → 通过YY机制保障 → 如有违约按ZZ处理」

【硬约束】
- 禁止：「设置项目负责人和各专项小组」——没说清楚每个组具体做什么
- 禁止：「具有丰富经验」——必须用年限/项目数/证书编号替换所有形容词
- 禁止：服务目标用「提供优质服务」——按四维度展开后给具体指标
- 必须：服务承诺和保障措施一一对应——每一句承诺都能追溯到方案中的具体机制
- 必须：所有流程描述到「一个新入职员工读完就能执行的粒度」
  → 反例：「每月按时完成薪酬核算」
  → 正例：「每月X日前，薪酬专员从考勤系统导出数据→核对加班/请假/调休→代入薪资公式→编制工资表→经项目负责人审核→提交甲方确认→X日前完成发放」
- 风格：方案书式，读完能直接作为团队的SOP手册
```

### 二、应急保障方案

```
你是项目风险管控负责人。请撰写「应急保障方案」章节：

【必须包含的应急场景（不少于 4 个）】
根据项目类型选择或自定义：
- 业务量骤增应急：客户临时增加X%业务量 → 储备人员/资源如何调配？响应时限？
- 关键人员流失应急：核心岗位突然离职 → 替代人选安排？替补到岗周期？交接机制？
- 重大事故应急：工伤/安全事故/法律纠纷 → 现场处置流程+升级汇报+善后方案
- 服务质量滑坡应急：满意度连续下降 → 预警机制+改进计划+甲方沟通机制
- 系统/设备故障应急：关键业务系统瘫痪 → 手工过渡方案+恢复流程
- 政策法规变更应急：新法规突然要求调整服务 → 快速响应和合规调整机制

每个场景按五要素结构写：
触发条件(可观测的信号) → 影响评估(对业务的具体影响) → 响应流程(分步，每步责任人+时限) → 恢复目标(恢复到正常状态的标准) → 事后复盘
→ 标准：预案的细节多到让人感觉「他们真遇到过这种状况并处理过」

【硬约束】
- 禁止：「及时处理」「妥善应对」——应急方案的价值在于「预案」中的「预」，不是「事后处理」
- 禁止：只写 1-2 个场景（看起来像套模板凑数）
- 必须：每个预案让评标专家产生「这个是真实排练过的」感觉
- 风格：故障场景剧本式，每个场景可独立演练
```

### 三、服务团队配置

```
你是服务团队负责人。请撰写「服务团队配置」章节：

【约束】
- 核心岗位清单（根据项目类型调整）：
  → 项目负责人：管理年限 | 同类项目数 | 相关证书编号
  → 业务主管/组长：业务年限 | 管理幅度（管理过X人团队） | 核心技能
  → 专项岗位：根据招标文件要求的持证上岗岗位
- 每个核心岗位四要素：姓名/学历 | 从业年限 | 专业证书编号 | 同类项目的量化成果
  → 量化成果示例：「主导过3个500人以上的劳务派遣项目，累计管理人数2000+」
  → 量化成果反例：「参与过多个大型项目」——完全不可验证
- 如招标文件要求特定证书（人力资源管理师/安全员/法律职业资格等），必须逐人点名谁持有
- 本地化能力（如有加分）：办公地点（附证明）+ 本地人员比例 + 本地资源覆盖
- 禁止：团队描述全是「资深」「丰富」等无法核查的形容词
- 必须：每条资质说明都标注支持材料的位置（如「见附件X-XX证书复印件」）
- 风格：简历式 + 资质清单式，信息密度高
```

### 四、逐条响应招标文件服务要求

```
你是投标响应负责人。请撰写「服务要求逐条响应」章节：

【核心原则】
招标文件通常会列出具体的「服务要求」（10-30条不等）。
每条必须独立响应，不可跳过。这是服务采购类废标的头号风险。

【格式要求】
三列格式：「招标要求(原文引述) → 我方响应(≥2句的具体措施) → 支撑材料(对应章节/附件)」

→ 反例响应：「完全响应招标文件要求」——一句话写完，得零分
→ 正例响应：「我方在服务方案第三章已建立薪酬核算SOP(详见3.2节)，配置专职薪酬专员2名(持有XX证书)，采用XX系统辅助核算并三重审核，确保每月X日前完成。详见服务方案3.2节及附件X-薪酬专员资质证书。」

【硬约束】
- 逐条独立响应，不可合并多条为一条
- 每条响应 ≥2 句话（说明怎么做 + 支撑在哪）
- 禁止：所有条款统一写「完全响应，详见服务方案」——这是废标级别的敷衍
- 必须：带★号的服务要求（实质性要求）逐字核对，确认响应方案100%覆盖
- 风格：对照表式，让评审一目了然地逐条打钩
```

### 五、商务部分

```
你是商务负责人。请补充以下内容：

【必须包含】
- 同类业绩表：年份 | 客户名称 | 项目名称 | 合同/结算金额 | 服务规模 | 服务期限 | 甲方评价等级
  → 如果招标文件区分「同级政府」「同行业」加分，单独分组并显著标注
- 客户评价/年度考核结果：如有「优秀」评价，用表格形式显著呈现
- 财务数据：按招标文件要求年份提供审计报告关键指标摘要
- 资质证照：营业执照 + 行业许可证（编号+有效期） + 体系认证（编号+有效期）

【硬约束】
- 业绩：表格形式，每个项目一行，信息密度高（不是大段文字描述）
- 禁止：业绩列表中用文字描述替代表格
- 风格：表格式
```
