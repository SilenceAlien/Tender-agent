# 上下文预算与加载策略（修正版 v2）

## 核心问题

WorkBuddy 的上下文窗口是有限的。上下文消耗 = **注入层** + **对话层**，两层的风险来源不同：

| 层 | 风险来源 | 典型大小 | 可控性 |
|----|---------|---------|--------|
| 注入层 | MEMORY.md + reference + 模板 + Skill | 1800-3100 tokens | 高（我们设计的重点） |
| 对话层 | 系统提示 + 对话历史 + 输出 | 3500-10000+ tokens | 中（轮次控制） |
| **合计** | | **5000-13000+ tokens** | |

## 三层加载策略

```
┌─────────────────────────────────────────────────┐
│  Tier 1: 常驻层 (目标 ≤500t，硬上限 800t)          │
│  MEMORY.md 精简版 — 每次对话自动加载              │
│  只存：项目元信息 + 核心策略 + 评分要点 + 当前阶段  │
│  不存：详细术语、长篇策略、历史决策全文            │
├─────────────────────────────────────────────────┤
│  Tier 2: 场景加载层 (按需，1-2个文件)              │
│  触发：Skill 判断任务类型后加载                   │
│  规则：加载前向用户确认，避免误判                  │
│  内容：术语表 / 评分标准 / 客户分析 / 竞品情报     │
├─────────────────────────────────────────────────┤
│  Tier 3: 显式加载层 (用户/Skill 明确引用)          │
│  存储：.workbuddy/prompts/ 目录                  │
│  内容：提示词模板、历史日志、参考文档              │
│  加载方式：用户明确要求 或 Skill 内部引用路径      │
└─────────────────────────────────────────────────┘
```

> **为什么 prompts/ 不在 memory/ 下？** 提示词模板是工具/资产，不是记忆。将它们放在 `.workbuddy/prompts/` 作为独立资产层，语义更清晰，避免了 "模板是否是记忆的一部分" 的混淆。

## 各层加载规则

### Tier 1（常驻）

- 内容: MEMORY.md 精简版
- 大小: 目标 ≤ 500 tokens，硬上限 800 tokens
- **维护方式**：
  - 不是「自动拆分」（WorkBuddy 无守护进程）
  - 通过「上下文维护 Skill」手动触发或「每日同步」自动化触发
  - 检测到超限时提示用户拆分

**Token 估算方法（实用，无需库）**：
- 中文：字数 × 1.5 ≈ tokens
- 英文：单词数 × 1.3 ≈ tokens
- 混合文本：取两者较高值

### Tier 2（场景加载）

- **触发**: Skill 或 Expert 被调用时

**加载选择逻辑（含协商步骤）**：

| 任务类型 | 默认加载 | 可选加载 |
|---------|---------|---------|
| 写技术方案 | reference/评分标准.md（技术部分）+ reference/术语表.md | reference/竞品分析.md |
| 写商务方案 | reference/客户分析.md + reference/术语表.md | reference/评分标准.md（商务部分） |
| 格式审查 | reference/格式检查清单.md | - |
| 报价计算 | reference/报价策略.md + reference/竞品分析.md | reference/客户分析.md |

**协商机制**：Skill 判断任务类型后，向用户确认：
> "我判断这是 [技术方案] 任务，将加载评分标准（技术部分）和术语表。需要加载竞品分析或调整为其他文件吗？"

### Tier 3（显式加载）

- 用户明确说 "加载 XX 文件"
- 或 Skill 内部通过路径引用（如 `prompts/技术方案/系统架构.md`）
- 完整的提示词模板文件
- 历史每日日志
- 大型参考文档

## Skill 自身的 Token 预算

每个 Skill 的 SKILL.md 自身控制大小：

| 约束 | 建议值 | 反例 |
|------|--------|------|
| SKILL.md 正文 | ≤ 800 tokens | 把完整提示词模板 + 领域知识塞进 SKILL.md |
| 内嵌提示词模板 | 放在 prompts/ 目录，通过路径引用 | 在 SKILL.md 中写 500+ tokens 的模板 |
| 领域知识 | 放在 references/ 目录，按需让 AI 读取 | 默认加载所有知识 |

## 全链路预算模型（含对话层）

```
一次"生成技术方案第三章"任务的真实消耗：

【注入层】
MEMORY.md (Tier 1)               ~600 tokens
评分标准-技术部分 (Tier 2)         ~500 tokens
系统架构模板 (Tier 3)              ~600 tokens
Skill 自身定义                     ~300 tokens
小计                              ~2000 tokens  ✓

【对话层】（已有 10 轮对话积累）
系统提示词                         ~2000 tokens
对话历史（10轮）                    ~2500 tokens
本次生成输出（预估）                 ~2000 tokens
小计                              ~6500 tokens

═══════════════════════════════════════════
总计                              ~8500 tokens
在 128K 窗口下完全安全
在 32K 窗口下仍有充足余量
```

## 对话层风险控制

这是上一版方案完全遗漏的部分：

| 风险场景 | 对话轮次 | 对话历史 tokens | 建议 |
|---------|---------|----------------|------|
| 正常 | < 10 轮 | < 2500 | 无需操作 |
| 关注 | 10-20 轮 | 2500-5000 | Skill 提示用户注意 |
| 警告 | 20-30 轮 | 5000-8000 | 建议执行摘要压缩 |
| 危险 | > 30 轮 | > 8000 | 强烈建议开新窗口 |

**摘要压缩操作**：
1. 让 Skill 将当前对话的关键决策写入 MEMORY.md 或当天的日志
2. 开新窗口/新对话
3. 新对话自动加载 MEMORY.md，拥有之前所有关键决策的上下文
4. 核心原理：**用 MEMORY.md 替代对话历史，500 tokens 替代 5000 tokens**

## 超出预算时的降级策略

| 触发条件 | 动作 | 谁执行 |
|---------|------|--------|
| MEMORY.md > 800t | 拆分详细内容到 reference/ | 上下文维护 Skill（手动触发 或 每日自动化任务） |
| 决策条目 > 5 条 | 旧条目归档到 reference/decisions.md | 同上 |
| 每日日志 > 30 天 | 合并归档，删除旧文件 | 自动化任务（每月执行） |
| 注入层 > 2500t | 提示用户缩小范围 | 上下文注入 Skill（实时） |
| 对话 > 15 轮 | 建议执行摘要压缩 | Skill 主动提示 |

## 监控指标

| 指标 | 健康值 | 告警值 | 检查方式 |
|------|--------|--------|---------|
| MEMORY.md tokens | < 500 | > 800 | 字数×1.5 估算 |
| 注入层总 tokens | < 2000 | > 2500 | Skill 累加估算 |
| 对话轮次 | < 10 | > 15 | Skill 记录 |
| Tier 2 加载文件数 | 1-2 | > 3 | Skill 检查 |
