## 标书 Agent 落地管道扩展分析

### 任务
用户追问：如果这个 agent 准备落地，当前工作流是否过于简单，是否需要优化或新增管道节点。

### 完成内容
- 对照真实标书生产全流程（约 14 个环节），识别当前 7 节点管道只覆盖 4-5 个，缺失 10 个
- 设计落地版 8 层分层管道：L0 入库 / L1 决策（Go/No-Go 门禁）/ L2 需求 / L3 策略 / L4 生成 / L5 校验（三道关）/ L6 人工 / L7 封装
- 三维度评分（废标风险/中标影响/法律必须）量化每个缺失环节的落地阻碍度
- 输出管道对比图（当前单线 vs 落地分层）+ 阻碍度柱状图
- 生成落地扩展方案文档：`specs/005-optimization-plan/landing-pipeline-expansion.md`

### 关键结论
- 当前管道是"格式转换器"（PDF→DOCX），落地需要"生产链"（带门禁+卡点+三道校验）
- 缺失 10 环节中 4 个是 MVP 必须（P0）：
  1. EligibilityChecker（资质门槛校验，L1 决策门禁，不满足直接终止避免浪费）
  2. ComplianceChecker（格式+法律合规，绝对化用语/虚假业绩直接废标）
  3. HumanReviewGate（人工审核卡点，法律必须，法定代表人签字不可全自动化）
  4. CrossReferenceChecker（跨章节一致性，人员数/技术参数跨章打架会被扣分）
- 落地 MVP 约 16 天（紧急修复 2 + spec.md 深化 5 + 新增 4 节点 9），成熟版约 5 周
- 最大非技术阻碍是数据：企业资质库、历史业绩库、法务规则库都需准备

### 三份文档关系
- `workflow-review.md`：现有 7 节点的漏洞诊断（质量审查，纵向）
- `landing-pipeline-expansion.md`：管道结构的横向扩展（架构补全，本文档）
- `spec.md`：现有 7 节点的深化优化（纵向深化）
执行顺序：紧急修复 → spec.md 阶段1 + 本文 MVP-1~4 并行 → spec.md 阶段2 + 本文 P1 → 远期增强
